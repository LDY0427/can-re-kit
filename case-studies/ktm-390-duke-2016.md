# Case study: decoding the KTM 390 Duke (2016) stock ECU diagnostic CAN

[한국어](ko/ktm-390-duke-2016.md)

A student Formula car uses the engine and stock ECU of a first-generation KTM 390 Duke (2016). This is how we built a signal table from three vehicle measurements in November 2026. Result: [profiles/ktm-390-duke-2016.yaml](../profiles/ktm-390-duke-2016.yaml).

## Starting point

- Goal: get engine RPM, throttle, coolant and MAP into the logger and the dash (shift light).
- Vehicle state: no ABS fitted and the stock dash off the bus, so **the engine ECU was the only node on the bus**. A fuel/ignition module sits after the ECU.
- Public information (from research; all `reported`):
  - 6-pin diagnostic connector: 1 +12 V, 2 CAN-H, 3 CAN-L, 6 ground (three sources agree).
  - 500 kbps, 11-bit, request `7DF` → answer `7E8` (compatibility information for a sibling displacement).
  - Standard RPM `01 0C` gets no answer on this year; RPM is read with a manufacturer request `21 21`, and one forum post says "÷ 264.12".
  - A public broadcast ID table exists for larger models (690, 1290), but nothing showed it applies to the first-generation 390. We did not use it.
  - There was one public firmware for the first-generation 390, but it had only been tested against a simulator and included features that send security-access and session-change requests. We did not follow it.

## Measurement 1 — does anything answer? (ELM327, day 1)

- Laptop + ELM327 (Bluetooth). Key ON, engine off.
- `01 00` answered at 500 kbps right away → bitrate and wiring confirmed.
- 17 standard PIDs supported. `01 0C` (RPM) no answer, as public sources said.
- Scan `21 00`–`21 FF`: **37 identifiers answered** (all between `21 20` and `21 66`).
- Lesson: an ELM327 manages only about 9 reads per second. That is the adapter and Bluetooth, not the ECU.

## Measurement 2 — finding meaning (day 2)

- Same equipment. Engine off with throttle only (closed ↔ wide open); after start, idle to 9,700 rpm (no load, vehicle stationary). Coolant 29–51 °C.
- Held against standard values:

| ID | Meaning | Formula | How it was confirmed |
|---|---|---|---|
| `21 21` | RPM | value ÷ 4 | Cumulative counter `21 64` rose 5,294/min ↔ time-weighted mean 5,268 rpm (ratio 1.005) |
| `21 64` | Crank revolutions since start | as is | 0 with engine off, only rises when running |
| `21 63` | Half of `21 64` | as is | Ratio 2.00–2.02 (looks like combustion count on a 4-stroke) |
| `21 3B` | Throttle sensor value | ≈ 0.0243 × value % | vs standard `01 11`, engine off r 1.000 (84 samples) |
| `21 22` | Coolant | 0.75 × value − 48 °C | vs standard `01 05`, r 0.99 |
| `21 4A` | MAP | value ÷ 256 kPa | vs standard `01 0B` over 26–117 kPa, r 0.993 |
| `21 42` | Engine running flag | 00/01 | 7 logs |

- Instead of the forum's 264.12 we took the physically sensible 256 (÷ 4) as the hypothesis and **cross-checked it independently with the cumulative counter**. Confirmed within ±5 %; the 3 % difference (256 vs 264.12) is not yet settled.
- For a while `21 27` was listed as an injection-time candidate, but in a log with many samples it correlated with neither MAP nor RPM (0.37 or less), so it was withdrawn.
- The oxygen sensor read a fixed 0.46 V and fuel trim a fixed 0 %. The cause was wiring, not the value: the sensor was connected to the aftermarket module, not the ECU. **If a value is stuck, check the wiring first.**

## Measurement 3 — measuring the ECU's limit directly on the bus (day 3)

- A direct tool built from an ESP32-S3 and a CAN transceiver module ([firmware/](../firmware/)).
- 200 s listening (key ON, engine off): **0 broadcast frames.** On this vehicle values come only by request/response.
- Answer limit: **100 per second (10 ms spacing)**, reproduced twice. At 5 ms spacing every answer was late. Latency 0.7–11.1 ms in a 10 ms saw-tooth → the ECU appears to process diagnostic requests on a 10 ms cycle.
- Engine running, 20 ms spacing for 5 minutes: all 15,000 succeeded, 0–10,288 rpm.
- Trouble codes:
  - P1505 appeared **during a 51 s stretch with no requests** (1.8 s before RPM became readable).
  - After the 5-minute poll, P0108 was added to the current-cycle codes. Whether the requests caused it is still unknown. Planned: run the same time without requests and compare.
- CAN-H–L resistance 127 Ω (key OFF) → one terminator.

## What the results meant for the design

- One device (the control module) sends requests; the logger and dash only listen to its answers.
- Share the 100 per second. RPM `21 21` for the shift light gets the most.
- With no broadcast frames, a listen-only device on its own receives nothing. A listening device is useful only when a requesting device is present.

## Still unknown

- Whether there are broadcast frames while the engine runs (we only listened with the engine off).
- Meaning of `21 24` `25` `26` `27` `2B` `2C` `3F`, and which identifier is injection time → a loaded road log.
- Meaning of manufacturer codes P1502, P1505, P1506, P1601, P1606, P1607.
- Why MAP reads 116–117 kPa with the engine off (ambient about 101 kPa) → compare with another gauge.
- The last 3 % of the RPM scale → hold a steady RPM and compare with the counter.

## Lessons that generalise

1. Listen first; if it is quiet, ask. A bus with only the ECU on it can be quiet.
2. Read standard PIDs alongside as a ruler. Without one you cannot find meaning.
3. A cumulative counter is an independent check of an RPM scale.
4. Before someone's formula with a strange number, put the physically sensible one first and decide by test.
5. Do not confuse the adapter's limit with the ECU's.
6. Write down trouble codes before and after measuring. Do not immediately blame a new code on your requests.
7. If a value is stuck, check the wiring first.
